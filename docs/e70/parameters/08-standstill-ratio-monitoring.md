# Standstill functions & gear-ratio monitoring

This group covers two unrelated-looking but equally "background" subsystems of the 8HP TCU. The first is the **standstill / neutral-idle function**: when the car is stopped in Drive with the brake applied, the TCU partially releases an input clutch so the torque converter is no longer dragging against a fully engaged gearset. This cuts idle load, vibration and heat. The parameter set covers the whole state machine of that feature — the entry conditions (temperature, time, turbine speed), the controlled *opening* of the clutch, a closed-loop *slip control* phase that holds the element at a small calibrated slip, and the *refill* ramp that re-engages the clutch crisply when the brake is released. The second subsystem is **gear-ratio plausibility monitoring** (`ratio_mon_*`): the TCU continuously computes the actual input/output speed ratio and compares it against calibrated upper/lower bands and per-shift tolerance curves. A ratio outside the band for the commanded gear indicates a slipping or failed clutch and leads to fault handling (DTC / limp strategy).

The two interact in one practical way for a tuner: aggressive changes to clutch pressures or shift behaviour elsewhere in the calibration can push transient ratios closer to the monitoring bands, so it is worth knowing where these tables live — but they are *diagnostic thresholds*, not performance maps. Everything in this group was identified by static reverse engineering (byte-identical object matches against a reference "F" build, reader-function analysis, cross-version comparison); the RE names are strong hints, but every functional interpretation here is **MED or LOW confidence** (nothing in this group is rated HIGH) and no table in this group should be edited casually.

### Standstill: neutral idle

32 items, calibration addresses 0x19AC48–0x19E8xx plus one outlier at 0x1ADE40. These parameters drive the neutral-idle (standstill decoupling) controller. Attribution is mixed: the f32 and s16 *curve* families were largely identified via reader-function analysis (the `e_ctrl_tcc_adp` control-flow proposal), while the f32 *maps* (press ramp, slip gain/press/time, torque limit) and the remaining s16/u8 items rest on byte-identical object matches with the reference F build — most of those maps have no reader bound in this build, only block membership. Several maps carry flat stock data (a single value across all cells), i.e. they act as constants in this calibration.

Rough functional flow, inferred from the names (treat as MED confidence at best): enable/condition curves (`nidle_temp_curve`, `nidle_time_temp_d8`, `nidle_curve_e4/f8`) gate the feature → `nidle_open_*` families schedule the controlled clutch opening → `nidle_slip_*` and `nidle_target_curves` run the closed-loop slip phase → `nidle_fill_curves` and `nidle_press_ramp_map` govern the refill/re-engagement.

**Tuning note:** for a swap, this whole family is best left stock unless you have a specific standstill-shudder or harsh re-engagement problem. The slip-controller maps (gain/press/time) interact as a closed loop; changing one without logging actual slip is likely to make re-engagement worse, not better.

### Gear ratio monitoring

35 items, 0x1C77E0–0x1C8630 plus `ratio_slip_map` at 0x1CB7CE. These tables define the plausibility windows the TCU uses to decide whether the measured gear ratio (turbine speed vs. output speed) matches the commanded gear, both in steady state and during shifts. In a clutch-to-clutch gearbox this is the primary detector for a slipping or non-applying clutch: if the ratio leaves the allowed band, the TCU registers a ratio fault (DTC, possible limp-home). The band/offset z-values are raw s16 (many saturate at 32767 = "no limit"); the outlying `ratio_slip_map` is u16. The RE evidence explicitly notes the **engineering unit of the values is not proven** — they are ratio-scaled internal quantities.

**Do not widen these bands to "fix" a ratio DTC** — the DTC is telling you a clutch is slipping. Narrowing them will produce false faults. The only legitimate reason to touch them would be a hardware change that genuinely alters the plausible ratio window, and even then the per-set/per-shift indexing below is only partially proven.
